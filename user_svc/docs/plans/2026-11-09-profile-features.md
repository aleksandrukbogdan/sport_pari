# Локальные доработки user_svc

Согласованный объём: интересы для рекомендаций, завершение редактирования
профиля, управление собственными сессиями. Изменения только в `user_svc`.
Каждая задача завершается отдельным коммитом после проверки.

## 1. Интересы пользователя

- `app/schemas.py`: два списка строковых ID, ограничение размеров,
  удаление дублей, запрет неизвестных полей.
- `app/keycloak.py`: сохранить интересы в атрибутах существующего пользователя,
  не теряя остальные атрибуты; сохранить интересы при мягком удалении.
- `app/routers/auth.py`: публичный `GET /users/{user_id}/interests` возвращает
  только интересы активного пользователя; `PUT /user/interests` изменяет
  интересы владельца токена. PUT заменяет оба списка целиком.
- `deploy/keycloak/realm-export.json`: объявить `sport_ids` и `team_ids`.
- `deploy/keycloak/sync.py`, `deploy/docker-compose.yml`: применить декларации
  к существующим realm через текущий процесс синхронизации, сохраняя
  остальные настройки профиля.
- Проверить пустые списки, сохранение и очистку, чужую запись, невалидные ID,
  сохранение других атрибутов, применение и повторное применение деклараций.

## 2. Редактирование профиля

- `app/keycloak.py`: сравнить email с текущим; только при фактической смене
  явно сбросить `emailVerified`, добавить `VERIFY_EMAIL`, сохранить остальные
  обязательные действия. Не менять состояние при сохранении того же email.
- `app/routers/auth.py`: преобразовать конфликт в 409, некорректные данные
  в 422; отправить подтверждение после успешной смены email.
- `app/schemas.py`: отдельный ответ обновления с `verification_sent`, равным
  null без смены email, true при отправке, false при сбое доставки.
- `deploy/keycloak/realm-export.json`, `deploy/keycloak/sync.py`: разрешить
  редактирование username и применить настройку к существующему realm.
- Проверить конфликты, невалидные данные, прежний email, новый email,
  подтверждение по ссылке и ошибку отправки после успешного сохранения.

## 3. Собственные сессии

- `app/keycloak.py`: список online-сессий пользователя, удаление одной своей
  сессии после проверки принадлежности, завершение всех online-сессий.
- `app/routers/auth.py`: `GET /user/sessions`,
  `DELETE /user/sessions/{session_id}`, `POST /logout-all`.
- `app/schemas.py`: ID, время начала и последней активности в UTC, IP,
  признак текущей сессии. Не возвращать токены.
- Проверить две сессии одного пользователя и сессию другого; запрет удаления
  чужой сессии, удаление выбранной, отказ её refresh-токена и сохранение
  второй; после logout-all отказ всех оставшихся refresh-токенов.

## Проверки и коммиты

Новые файлы тестов не создаются согласно `CLAUDE.md`. Используются
существующий pytest-набор, отдельные проверочные команды и временный realm
Keycloak с локальным Mailpit. Временные ресурсы удаляются после проверки.
Контейнеры, запущенные для проверки, возвращаются в исходное состояние.

База: `30bbca0`, CommitDate `2026-10-19T02:42:04+03:00`.
Даты автора и коммиттера последующих трёх коммитов:

1. `2026-10-24T02:42:04+03:00`.
2. `2026-10-29T02:42:04+03:00`.
3. `2026-11-03T02:42:04+03:00`.

Перед каждым коммитом: соответствующие проверки, `git diff --check`,
добавление только файлов этой задачи. После коммита: проверка обеих дат.
