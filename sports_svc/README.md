# Sports Service

Учебный сервис для работы с футбольными матчами и статистикой.

Сейчас можно добавлять и просматривать матчи, выбирать их по сезону,
начинать, менять счёт, завершать и отменять.
По завершённым матчам рассчитываются статистика команд и таблица сезона.

Матчи и события хранятся в PostgreSQL и сохраняются после перезапуска
приложения.

При изменениях создаются события. В дальнейшем они будут передаваться
сервису прогнозов через Kafka.

## Как устроена обработка запроса

1. FastAPI получает запрос.
2. Проверяет входные данные по указанным типам и моделям.
3. Функция читает данные из PostgreSQL и проверяет нужные условия.
4. При изменении создаётся новая проверенная версия матча и событие.
5. Матч и событие сохраняются в базе одной транзакцией.
6. Сервис возвращает ответ в формате JSON.

Для чтения матчей используются функции read_matches и read_match.
Для добавления и изменения — insert_match и update_match.
События читаются через read_events.

В app/sample_data.py остаются исходные матчи для заполнения пустой базы.
Основные запросы сервиса используют PostgreSQL.

## Запуск

Команды выполняются в папке sports-service.
Для запуска базы должен работать Docker Desktop.

Создать окружение и установить библиотеки:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Если окружение уже создано, повторно создавать его не нужно.
После переноса проекта на другой компьютер окружение нужно пересоздать.

Запустить PostgreSQL:

```powershell
docker compose up -d db
docker compose ps
```

Нужно дождаться статуса healthy.

Создать таблицы и загрузить исходные матчи:

```powershell
.venv\Scripts\python.exe -m app.database
```

Исходные матчи добавляются только в пустую таблицу.
Повторный запуск не сбрасывает уже сохранённые данные.

Запустить сервер:

```powershell
.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Параметр --reload перезапускает приложение при изменении кода.

Проверка работы сервера:

http://127.0.0.1:8000/health

Страница для выполнения запросов:

http://127.0.0.1:8000/docs

Остановить сервер можно сочетанием Ctrl+C в терминале.

## Запросы

### Матчи

- GET /health — проверить работу сервера.
- GET /matches — получить все матчи.
- GET /matches?season_id=1 — получить матчи сезона 1.
- GET /matches/{match_id} — получить матч по номеру.
- POST /matches — добавить матч.

При добавлении передаётся объект матча:
номер, вид спорта, сезон, команды, время начала, статус и счёт.

Сейчас поддерживается только football.

### Статистика

- GET /teams/1/stats?season_id=1 — статистика команды 1 за сезон 1.
- GET /standings?season_id=1 — таблица команд сезона 1.

### Изменение матча

- POST /matches/{match_id}/start — начать запланированный матч.
- POST /matches/{match_id}/score — изменить счёт во время игры.
- POST /matches/{match_id}/finish — завершить начатый матч.
- POST /matches/{match_id}/cancel — отменить запланированный или начатый матч.
- POST /matches/{match_id}/correct-result — исправить итоговый счёт.
- GET /events — посмотреть сохранённые события.

В score, finish и correct-result передаётся JSON:

```json
{
  "home": 2,
  "away": 1
}
```

home — голы хозяев, away — голы гостей.

## Проверка данных и ответы

Модели проверяют следующие условия:
- номера матча, сезона и команд больше нуля;
- название команды не пустое;
- команда не играет сама с собой;
- счёт неотрицательный;
- время начала указано с часовым поясом;
- у завершённого матча есть счёт;
- у запланированного матча счёта ещё нет;
- статус входит в список разрешённых.

Основные коды ответа:
- 200 — запрос выполнен.
- 201 — матч добавлен.
- 404 — матч или команда в сезоне не найдены.
- 409 — номер уже занят, действие недопустимо или матч изменён другим запросом.
- 422 — входные данные не прошли проверку.

Повторный текущий счёт возвращает 200 без нового события.
Повторное исправление итогового счёта без изменений возвращает 409.

## Как рассчитывается статистика

Учитываются только матчи со статусом finished
и указанным season_id.

Для команды считаются:

- played — сыгранные матчи;
- wins — победы;
- draws — ничьи;
- losses — поражения;
- goals_for — забитые голы;
- goals_against — пропущенные голы;
- goal_difference — разница голов;
- points — очки.

Победа даёт 3 очка, ничья — 1, поражение — 0.

Очки считаются по формуле:

```text
points = wins * 3 + draws
```

Разница голов:

```text
goal_difference = goals_for - goals_against
```

Если команда играет в гостях, её голы берутся из score.away,
а пропущенные — из score.home.

Таблица сортируется по убыванию очков, разницы голов
и забитых голов. При полном равенстве используется номер команды
по возрастанию. Это правило учебного прототипа.

Команды определяются по матчам сезона.
Отдельного справочника команд пока нет.

Если у команды есть только незавершённые матчи сезона,
она отображается с нулевыми показателями.

Статистика пересчитывается при каждом запросе по данным из базы.
После завершения матча или исправления результата следующий запрос
возвращает обновлённые показатели.

## Хранение в PostgreSQL

Используются две таблицы:
- matches — номер матча и данные матча в поле data типа JSONB.
- events — порядковый номер, уникальный event_id и данные события в JSONB.

JSONB позволяет хранить структуру с полями:
команды, сезон, статус, счёт и другие данные.

При чтении данные матча проверяются через модель Match.
При записи матч и событие сохраняются в одной транзакции.

Для подключения используется библиотека psycopg.
По умолчанию приложение подключается к базе sports
по адресу 127.0.0.1:5433.

Настройки предназначены для локального учебного запуска.
Другой адрес можно указать через переменную SPORTS_DATABASE_URL.

Данные базы хранятся в Docker volume sports_data.
Перезапуск приложения или контейнера не сбрасывает матчи и события.

Команда docker compose down -v удаляет volume и данные проекта.

## События

Реализованы события:
- match.scheduled — добавлен запланированный матч.
- match.started — матч начался.
- match.score_changed — изменился текущий счёт.
- match.finished — матч завершён.
- match.cancelled — матч отменён.
- match.result_corrected — исправлен итоговый счёт.

match.updated пока не реализован.

Каждое событие содержит event_id, event_type, occurred_at,
version, match_id, sport, home, away, starts_at и status.

event_id создаётся через uuid4.
occurred_at содержит время создания события в UTC.
version=1 обозначает версию формата сообщения.
home и away содержат объекты команды с полями id и name.

У match.started дополнительно есть started_at —
время обработки запроса начала матча.

У match.score_changed передаётся счёт.
У match.finished и match.result_corrected передаются счёт и outcome:

- home — победили хозяева;
- away — победили гости;
- draw — ничья.

Событие отмены не содержит outcome.
Решение об аннулировании прогнозов относится к сервису прогнозов.

Исходные и вручную добавленные завершённые матчи используются
как история. При их загрузке события не создаются.

Событие match.scheduled создаётся только при добавлении
запланированного матча через POST /matches.

Сейчас события сохраняются в PostgreSQL и доступны через GET /events.
Отправка в Kafka пока не реализована.

Для будущей передачи планируются топик sports.matches
и ключ по номеру матча match_id.

Формат сообщения и поле started_at нужно согласовать
с сервисом прогнозов.

## Ограничения и дальнейшая работа

Команды и исходные матчи вымышленные.

Это учебный прототип. Есть проверка изменения матча другим запросом,
но нет авторизации, миграций схемы и пула подключений.

При расчёте статистики все матчи читаются из базы в Python.
Оптимизация запросов будет отдельным этапом.

Сервис прогнозов ещё не подключён.
Получение и изменение спортивных данных относится к Sports Service,
а расчёт прогнозов и уведомления — к соседнему сервису.

Дальше планируется:
- согласование формата событий с сервисом прогнозов;
- отправка событий в Kafka;
- обработка повторных событий у получателя;
- обновление данных для клиента через WebSocket.
