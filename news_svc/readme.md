# news_svc

Новостной сервис sport_pari. Хранит материалы, комментарии и историю открытий, импортирует спортивные RSS и формирует персональную ленту по интересам из `user_svc` и истории чтения.

## Что работает

- Лента опубликованных материалов, карточка, поиск по заголовку и тексту, фильтр вида спорта, пагинация и счётчики видимых комментариев. Черновики и запланированные публикации скрыты до даты публикации.
- Создание комментариев, редакторская модерация и восстановление скрытых комментариев.
- Импорт реальных новостей по 12 видам спорта из RSS BBC Sport и CBS Sports и публичного JSON ESPN с заголовком, анонсом, датой, источником, доступным изображением и оригиналом. Полный текст доступен у источника. Повторный импорт сохраняет уже загруженные материалы, их ID и историю взаимодействий.
- TF-IDF по заголовку и телу, персональный профиль чтения, популярность с затуханием и совпадение интересов по спорту и тегам команд.
- Профиль и изменение интересов через существующий `user_svc`, персональная лента с карточками и объяснением рекомендации.
- `/preview` с реальными материалами, подключением пользовательского профиля, поиском, комментариями и объяснением оценок.

## Как считаются рекомендации

На запрос берётся до 75 последних опубликованных материалов каждого вида спорта, суммарно до 1000. Кандидаты ограничены последними семью днями. Если таких материалов нет, используются доступные публикации из этого набора. TF-IDF обучается на этом корпусе в отдельном потоке. История пользователя читается из просмотров и видимых комментариев, глобальная популярность агрегируется в БД.

Вес события равен `event_weight × 0.5 ** (возраст_в_часах / 36)`. Просмотр имеет вес `1`, комментарий — `3`. Текстовый профиль пользователя является взвешенной суммой TF-IDF-векторов прочитанных материалов. Похожесть определяется косинусом между этим профилем и статьёй.

Итоговая оценка равна `0.5 × P / (1 + P) + 0.3 × cosine + 0.2 × interest_match`, где `P` — сумма затухающих весов событий. Совпадение вида спорта или явно заданного тега команды даёт `interest_match = 1`. ID команд берутся из `team_ids` статьи. Импортёр оставляет их пустыми, редактор может добавить ID каталога.

Непрочитанные материалы идут перед прочитанными. Внутри группы порядок определяется оценкой, при равенстве — датой публикации. `reason` показывает сигнал с наибольшим вкладом. Для нового пользователя без интересов и истории остаются популярность и порядок публикации. Сбой чтения интересов сохраняет выдачу. При недоступности проверки Bearer-токена защищённые действия возвращают 503.

Каждое открытие и повторное открытие — отдельное событие. Комментарии читаются из своей таблицы. Скрытие комментария исключает его из счётчика, текстового профиля и популярности при следующем расчёте.

## Связь с user_svc

Контракт сверяется с `origin/main`, `user_svc/docs/profile-api.md`.

- `GET {USER_SERVICE_URL}/user` с Bearer-токеном проверяет пользователя через Keycloak и возвращает его профиль. Его `id` используется для истории и комментариев.
- `GET {USER_SERVICE_URL}/users/{id}/interests` возвращает публичные `sport_ids` и `team_ids`.
- `PUT {USER_SERVICE_URL}/user/interests` с токеном владельца заменяет его интересы. Контракт списков совпадает с пользовательским сервисом.

В настройках новостной ленты `/preview/profile` можно выбрать виды спорта. Изменения записываются в `user_svc` и применяются при следующем запросе ленты. Существующие интересы к командам сохраняются; каталог для выбора команд пока не подключён.

Токен, полученный через `/login` в `user_svc`, передавайте как `Authorization: Bearer ...`. По умолчанию `X-User-Id` не авторизует запрос. Режим `TRUST_GATEWAY_HEADERS=true` предназначен для сети за доверенным шлюзом и используется в искусственном демо.

`/preview` выполняет вход по имени и паролю через `/login` пользовательского сервиса. Полученный access token проверяется через `/user` и сохраняется на 30 минут в HttpOnly cookie с SameSite=Strict. Для готового токена также доступен `POST /preview/session`. HTTPS включает Secure. Перед персональными действиями профиль проверяется повторно. Гость читает новости, для записи просмотра и комментария нужен профиль.

## Запуск с реальными новостями

Из каталога `news_svc` выполните команды.

```bash
uv sync
uv run python -m app.demo --real --port 8003 --user-service-url http://127.0.0.1:8000
```

Откройте [ленту](http://127.0.0.1:8003/preview). Реальные данные сохраняются в `.local/news.sqlite`, миграции применяются автоматически. Следующий запуск обновит RSS. `user_svc` должен работать по указанному адресу, чтобы подключить личный профиль. До подключения доступна гостевая лента.

Для искусственных сценариев используется `uv run python -m app.demo`. Он создаёт временную базу, пять вымышленных новостей, черновик и три профиля. Перезапуск сбрасывает историю. В футбольном профиле кубковый матч поднимается за счёт интереса и свежего просмотра. После открытия он уходит ниже непрочитанных. У хоккейного профиля выше новость про СКА. Из-за смеси сигналов популярная новость другого вида спорта может обойти менее популярную новость своего вида спорта.

## PostgreSQL и контейнеры

```bash
docker compose -f deploy/docker-compose.yml --profile ingest up --build
```

API доступен на [порту 8003](http://localhost:8003/docs), PostgreSQL — `127.0.0.1:5432`, база, пользователь и пароль — `news`. Профиль `ingest` включает обновление RSS каждые 15 минут. Контейнер API применяет миграции до запуска, импортёр ждёт готовности API. Для `/preview` перед запуском задайте `PREVIEW_ENABLED=true`.

Compose ожидает `user_svc` на `http://host.docker.internal:8000`. Другой адрес задаётся переменной `USER_SERVICE_URL`. Порты новостей и пользователей различаются. Редакторские ручки закрыты, пока не задан `ADMIN_API_KEY`.

Для запуска API без контейнера задайте `DATABASE_URL` и `USER_SERVICE_URL` в `.env` на основе `.env.example`.

```bash
uv sync
uv run alembic upgrade head
uv run python -m app.ingest
uv run uvicorn app.main:app --host 127.0.0.1 --port 8003
```

`uv run python -m app.ingest --interval 900` обновляет RSS в цикле. `NEWS_SOURCES` принимает JSON с одной ссылкой или списком ссылок для каждого вида спорта. Пример `{"football":"https://feeds.bbci.co.uk/sport/football/rss.xml"}`. Ошибка одного источника попадает в отчёт и сохраняет существующие новости. Однократный запуск с ошибкой завершается с ненулевым кодом. URL оригинала имеет уникальный индекс, поэтому параллельный импорт не создаёт дубликаты.

## API

Полные схемы доступны в `/docs`.

- `GET /api/v1/news?sport_id=football&q=final&limit=20&offset=0` — общая лента и поиск.
- `GET /api/v1/news/{id}` — карточка с текстом RSS-анонса или редакторского материала и источником.
- `GET /api/v1/news/{id}/comments` — видимые комментарии с пагинацией.
- `POST /api/v1/news/{id}/comments` — комментарий владельца токена, тело `{"body":"Текст"}`.
- `GET /api/v1/recommendations?limit=10` — ID, оценка и причина, требуется авторизация.
- `POST /api/v1/recommendations/views` — открытие статьи, тело `{"news_id":1}`, требуется авторизация.
- `GET /api/v1/me` — профиль владельца токена из `user_svc`.
- `GET /api/v1/me/interests` и `PUT /api/v1/me/interests` — чтение и замена интересов.
- `GET /api/v1/me/feed?limit=20&offset=0` — персональные карточки с рекомендацией и отметкой просмотра.

Редактор использует `X-API-Key`, равный `ADMIN_API_KEY`.

- `GET /api/v1/editor/news` — последние 100 материалов, включая черновики.
- `POST /api/v1/editor/news` — создание материала.
- `PUT /api/v1/editor/news/{id}` — полная замена полей материала. `published_at=null` снимает публикацию.
- `GET /api/v1/editor/comments` — последние 100 комментариев, включая скрытые.
- `PATCH /api/v1/editor/comments/{id}` — `{"is_hidden":true}` скрывает, `false` восстанавливает комментарий.

Пример создания редакторского материала.

```json
{
  "title": "Итоги матча",
  "summary": "Короткий анонс",
  "body": "Текст материала",
  "sport_id": "football",
  "team_ids": ["cska"],
  "published_at": "2026-11-15T12:00:00Z"
}
```

## Проверка качества

```bash
uv run pytest -q
uv run python -m app.recommendations.evaluate --cutoff 2026-11-14T00:00:00+00:00 --k 10
```

Recall@K считается на временном разбиении. TF-IDF и история строятся по данным до cutoff. Цели — открытия и комментарии после cutoff для ранее опубликованных, ещё не прочитанных пользователем статей. События будущего не попадают в признаки. При отсутствии подходящих событий `recall_at_k=null`. Импорт новостей сам по себе не создаёт историю чтения, поэтому качество рекомендаций требует реальных пользовательских взаимодействий.

## Проверенный локальный стенд

15 ноября 2026 года выполнена проверка с PostgreSQL 16, Keycloak 26 и актуальным `user_svc`. При первой загрузке импортировано 113 реальных материалов. После расширения импорта в ленте доступны 614 публикаций по 12 видам спорта, в том числе 92 по баскетболу и 87 по хоккею. Проверены вход, чтение профиля, сохранение интересов, персональная выдача, понижение открытого материала, комментарий, модерация и вход/изменение интересов/выход через `/preview`.

В `user_svc/app/keycloak.py` исправлена передача полей профиля в Keycloak при сохранении интересов, изменении профиля и мягком удалении. Частичная передача профиля очищала email и блокировала повторный вход. Изменение интересов проверено повторным входом и чтением сохранённого значения из пользовательского сервиса.


## Интерфейс новостей

Фронтенд News Service приведён к общей тёмной дизайн-системе sport_pari. Доступны общая и персональная ленты, поиск, фильтры, пагинация, статья с источником и изображением, комментарии и настройки новостных интересов. Технические иконки, кнопки, карточки и состояния переиспользуются из общего слоя. Описание структуры и проверки приведено в [docs/news-ui.md](docs/news-ui.md). Страница примеров компонентов доступна по `/preview/components`.

Виды спорта по умолчанию включают футбол, баскетбол, хоккей, теннис, Формулу-1, регби, крикет, лёгкую атлетику, гольф, велоспорт, бокс и бейсбол. Для баскетбола и хоккея подключены несколько источников. Импорт выполняет до четырёх сетевых запросов параллельно, а запись выполняется последовательно в транзакциях по источнику. Букмекерские рекламные заголовки исключаются из публикации.
