# Проверка доработок профиля

Проверки выполняются на собранном образе API с PostgreSQL и Keycloak 26.0
из текущего Compose. Для данных используется отдельный временный realm,
для почты — локальный Mailpit. Существующие пользователи и внешние почтовые
ящики не используются. Новые файлы тестов в репозиторий не добавляются.

## Интересы пользователя

Образ API: `sha256:d1226601eafd51c3cba0950d7a4ad5c6c4ca6c643dec6d4794d67b9b8d2ae47f`.

Проверены через HTTP к контейнеру API:

- пустые интересы существующего пользователя;
- запись, чтение, удаление дублей и пробелов, очистка обоих списков;
- 401 без токена, 422 для попытки передать чужой user_id;
- 422 для пустого ID, числа вместо строки, превышения 100 элементов;
- интересы другого пользователя не изменяются;
- ответ содержит только sport_ids и team_ids;
- 404 для отсутствующего и отключённого пользователя;
- сохранение других атрибутов при записи интересов и мягком удалении.

На realm без деклараций интересов проверены добавление деклараций через
`sync_user_profile`, сохранение стороннего атрибута и повторный вызов
без PUT к Keycloak.

Существующий набор: `python -m pytest tests -q` — **3 passed**.
`docker compose -f deploy/docker-compose.yml config --quiet` и
`git diff --check` завершились с кодом 0.

Временные контейнер API и realm удалены после проверки.
