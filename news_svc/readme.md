# news_svc

Новостной блок sport_pari: лента, карточка, комментарии и короткая выдача для пользователя.

## Было

Лента и комментарии уже читались и писались в Postgres. Рекомендации и запись просмотра были объявлены в API, но отвечали `501`: сервис собирал четыре зависимости и сразу выбрасывал `NotImplementedError`. Клиент интересов описывал JSON и не делал запрос.

## Стало

1. `GET /api/v1/recommendations` отдаёт опубликованные материалы. Черновик в список не попадает. Уже открытое остаётся в списке, но опускается ниже.
2. `POST /api/v1/recommendations/views` пишет открытие в `news_views`. Комментарий в эту таблицу не копируется. Чужого или чернового материала нет — `404`.
3. Интересы запрашиваются у сервиса пользователей. Если он ответил, совпавший вид спорта поднимается наверх (`reason=sport`). Если сервис молчит или ответ битый, лента всё равно приходит (`reason=popularity`).

## Почему

На ревью заглушка по правильному URL выглядела как готовая ручка: клиент упирался в стену. Длинная цепочка из ранкера, профиля и журнала просмотров при этом ничего не показывала. Поэтому выдача начинается с уже работающего списка опубликованных новостей, а зависимости передаются снаружи, как у ленты и комментариев.

TF-IDF в этот заход не встраивали. Журнала кликов ещё нет, а без него похожесть текста нечего учить. Сначала есть что открыть руками.

`X-User-Id` по-прежнему не проверяется внутри сервиса. Заголовок доверенный только за шлюзом: в платформе до процесса снаружи не ходят, JWT ставит gateway. Порт `8000` в compose опубликован для локальной проверки, это не боевая граница.

## Запуск

Из каталога `news_svc`:

```bash
docker compose -f deploy/docker-compose.yml up --build
uv run python -m app.seed
```

Контейнер сам выполняет `alembic upgrade head`. API: http://localhost:8000. Страница для просмотра: http://localhost:8000/preview. Порт в compose только для локальной машины.

```bash
curl -s -H 'X-User-Id: demo' http://localhost:8000/api/v1/recommendations
curl -s -X POST -H 'X-User-Id: demo' -H 'content-type: application/json' \
  -d '{"news_id":1}' http://localhost:8000/api/v1/recommendations/views
```

Postgres: база `news`, пользователь и пароль `news`, порт `localhost:5432`. `app.seed` кладёт три материала в пустую базу и повторно ничего не добавляет.

Локально без контейнера API:

```bash
uv sync
uv run alembic upgrade head
uv run python -m app.seed
uv run uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```
