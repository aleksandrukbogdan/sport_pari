# news_svc

Новостной блок sport_pari: лента, карточка материала, комментарии и заготовка лёгких рекомендаций.

## Было

В начале октября сервис уже умел ответить на `GET /health` и показать контракт ленты с комментариями. Маршруты, таблицы и схемы были размечены, репозитории поднимали `501`. Папки рекомендаций не было, сессии к Postgres тоже: схему ещё нечем было создавать, кроме будущего `create_all` при старте.

## Стало

1. Лента и карточка читают опубликованные материалы из Postgres. Черновик без `published_at` в выдачу не попадает. Счётчик комментариев считается отдельно от текста треда.
2. Комментарий можно прочитать и написать. Нет материала — `404`. Нет заголовка `X-User-Id` — `401`. Имя автора сервис не хранит.
3. Рядом лежит каркас рекомендаций: веса сигналов, `NewsRanker`, таблица просмотров и клиент интересов профиля. Эти ручки по-прежнему отвечают `501`, модель не обучается.

## Почему

Сначала попробовали собрать весь сервис одним заходом: поиск, сиды и запросы сразу. Ограничение стало видно быстро: в одном диффе смешались контракт и реализация, и ревьюить было нечего по частям. Поэтому оставили заглушки и разрезали историю на короткие коммиты.

Дальше упёрлись в сами заглушки. Пока лента отвечает `501`, блок нельзя открыть и не на чем проверить комментарий. В эту итерацию довели до базы только чтение и обсуждение: сессия на запрос и миграция Alembic, без создания таблиц при старте процесса.

Ранкер в те же запросы не стали вшивать. Без накопленных просмотров и текстов TF-IDF не на чем учить, а scikit-learn в образ на этом шаге только увеличил бы сборку. Каркас отделили, чтобы следующий PR менял поведение рекомендаций, а не раскладку папок.

## Запуск

Из каталога `news_svc`:

```bash
docker compose -f deploy/docker-compose.yml up --build
```

Контейнер сам выполняет `alembic upgrade head`. API: http://localhost:8000, OpenAPI: http://localhost:8000/docs.

Три демо-материала в пустую базу:

```bash
uv run python -m app.seed
```

Повторный запуск ничего не добавляет. Postgres в compose: база `news`, пользователь и пароль `news`, порт `localhost:5432`.

Локально без контейнера API, когда Postgres уже поднят:

```bash
uv sync
uv run alembic upgrade head
uv run python -m app.seed
uv run uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```
