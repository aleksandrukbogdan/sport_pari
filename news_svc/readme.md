# news_svc

Микросервис новостного блока sport_pari: лента, карточка материала, комментарии и лёгкие рекомендации.

Пользователь открывает блок новостей, фильтрует его по виду спорта, читает материал и оставляет комментарий. Для известного пользователя блок можно упорядочить по интересам. Аккаунты, линия и коэффициенты здесь не хранятся.

Сейчас маршруты и таблицы размечены, а запросы и обучение модели ещё не написаны: репозитории и ранкер поднимают `501 Not Implemented`.

## Стек

- **FastAPI**. Сервис уже на нём, BFF получает контракт из OpenAPI.
- **Postgres**. Лента — это сортировка и фильтр, комментарий — это ссылка на материал и автора. Для таких связей реляционная база подходит напрямую, и Postgres уже поднят в compose. Документная база была бы уместна, если тело новости станет деревом блоков. Пока это обычный текст, а если блоки появятся, их можно положить в JSONB, не вынося комментарии в другую базу.
- **SQLAlchemy 2 + asyncpg**. Тот же async-контур, что и у API. Сессии и миграции подключим, когда появятся первые запросы.

## Что нужно от других сервисов

- **Шлюз авторизации**. На запись комментария присылает заголовок `X-User-Id`. JWT этот сервис не проверяет и таблицу пользователей не заводит. Имена авторов для отрисовки собирает BFF из сервиса пользователей.
- **Каталог видов спорта**. `sport_id` на новости — это id каталога. Свой справочник видов спорта здесь не дублируется. Те же id должны приходить в интересах профиля, иначе «любит хоккей» не совпадёт ни с одним материалом.
- **Сервис пользователей, ручка интересов**. `GET {USER_SERVICE_URL}/users/{id}/interests` с полями `sport_ids` и `team_ids`. Это холодный старт: человеку без просмотров есть что показать в его видах спорта. Логин и JWT остаются на шлюзе. Если профиль — отдельный деплой, в `USER_SERVICE_URL` ставится он. Клиент лежит в `app/clients/user_service.py` и пока не делает запрос.

Редакционное создание новости в эти маршруты не входит: снаружи есть чтение ленты и чтение карточки.

## Рекомендации

Модель лёгкая и считается внутри этого сервиса. Отдельный ML-контур и нейросеть не нужны: материалов сотни, а не миллионы, а сигналов поначалу мало. Нейросеть на таком объёме запоминает нескольких активных пользователей и хуже объясняется.

Ранкер смешивает три вещи. Затухающую популярность: материал, который читают сейчас, важнее вчерашнего финала. Похожесть текста: TF-IDF по заголовку и телу, затем косинус с тем, что человек уже читал. Имена команд и турниров редкие, мешка слов достаточно. Совпадение вида спорта с профилем. Веса заданы руками в `features.py`, пока нет журнала кликов для маленькой логистической регрессии.

Обучение — офлайн-вызов `NewsRanker.fit`, не обработка HTTP-запроса. В запрос попадает только `rank` по свежему окну в 7 дней. Библиотеки для этого шага: scikit-learn (`TfidfVectorizer`, `cosine_similarity`), numpy для смеси оценок, pandas для таблиц обучения. В `pyproject.toml` их пока нет: заглушка не должна раздувать образ API обучением, которого ещё нет. PyTorch в этот стек не входит.

Просмотр пишет клиент или BFF в `POST /api/v1/recommendations/views`. Комментарий из этой таблицы не копируется: он уже лежит в `comments`, второй записью его легко посчитать дважды.

На что смотреть, когда появится оценка качества: разбиение по времени, не случайное; Recall@K, не accuracy; не подмешивать будущую популярность материала; не показывать повторно уже открытое. Просмотров будет гораздо больше, чем комментариев, поэтому у комментария вес выше.

## Запуск

Из каталога `news_svc`:

```bash
docker compose -f deploy/docker-compose.yml up --build
```

- API: http://localhost:8000
- OpenAPI: http://localhost:8000/docs

Проверка процесса:

```bash
curl -s http://localhost:8000/health
```

Лента, комментарии, рекомендации и запись просмотра пока отвечают `501`. Для `GET /api/v1/recommendations` и записи просмотра нужен заголовок `X-User-Id`.

Локально без контейнера API:

```bash
uv sync
uv run uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Образ собирается тем же `uv`: зависимости ставятся из `uv.lock`, каталог `app` импортируется из рабочей директории. Postgres в compose: база `news`, пользователь и пароль `news`, порт `localhost:5432`. Строка подключения — в `.env.example`.
