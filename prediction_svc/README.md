# Prediction Service

Сервис вопросов «да / нет». Пользователь голосует, денег и очков нет.

Вопрос создаёт администратор. Пользователи только голосуют и смотрят,
как меняется доля голосов «да».

## Кто может создавать вопросы

Запросы идут с заголовком `Authorization: Bearer <access-token>`.
Токен выдаёт User Service на `POST /login`. Идентификатор пользователя —
поле `sub`. Просроченный токен отклоняется.

Администратор — это `sub` из списка `ADMIN_USER_IDS` (по умолчанию `admin`).
Роли в токене пока нет, поэтому список задаётся настройкой.

- `POST /questions` — только администратор, ответ `201`.
- чужой пользователь получает `403`, запрос без токена — `401`.

Тело вопроса:

```json
{"title": "North победит?", "kind": "match", "match_external_id": "15"}
```

`kind` бывает `match` или `event`.

- `match` — вопрос про конкретный матч Sports. Нужен `match_external_id`,
  и этот матч уже должен лежать в локальной копии. Иначе `404`.
- `event` — любой другой вопрос игрового мира, например про драфт.
  `match_external_id` для него не сохраняется.

В карточке вопроса про матч видны `home_name`, `away_name`, `starts_at`
и `match_status` из копии матча.

## Как отфильтровать

`GET /questions` отдаёт все вопросы. Фильтр — query-параметр `kind`:

- `GET /questions?kind=match`
- `GET /questions?kind=event`

## Как читать график

`GET /questions/{id}/chart` возвращает точки. В каждой точке:

- `at` — момент голоса;
- `yes` и `no` — сколько человек сейчас держит этот выбор;
- `yes_share` — доля «да», от 0 до 1. Пока голосов нет, поле пустое.

Учитывается последний выбор каждого пользователя. Повтор того же голоса
не добавляет точку. Смена «да» на «нет» или обратно добавляет точку
и сдвигает долю.

Голос: `POST /questions/{id}/votes` с телом `{"choice": "yes"}` или
`{"choice": "no"}`.

## Когда голосование заканчивается

Администратор закрывает вопрос: `POST /questions/{id}/close`.
После этого новый голос получает `409`. Уже отданные голоса и график остаются.

Если по связанному матчу приходит `match.finished` или `match.result_corrected`,
вопрос закрывается сам, а в `factual_outcome` появляется исход `home`, `draw`
или `away`. Это справка по факту матча, очки никому не начисляются.

`match.cancelled` помечает связанные вопросы статусом `withdrawn`
и убирает исход.

## Откуда берутся факты о матче

Sports присылает события матча: создание, перенос, старт, счёт,
завершение, отмена, исправление результата. Сервис хранит копию матча
и по ней показывает карточку. Более позднее событие обновляет статус,
счёт и исход. Более раннее не затирает копию: Sports всегда присылает
`version: 1`, поэтому сравнение идёт по `occurred_at`. Новостной сервис не вызывается:
новости не являются фактом, по которому закрывается вопрос.
