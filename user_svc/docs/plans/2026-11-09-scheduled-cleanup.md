# Надёжная очистка удалённых пользователей

Согласованный объём: обработать все страницы пользователей Keycloak,
сравнивать сроки удаления с учётом часового пояса, пропускать повреждённые
даты у отдельных пользователей. Изменения только в `user_svc`.

## Реализация

- `app/keycloak.py`, `get_users_scheduled_for_deletion`: запросы по 100
  пользователей с `first` и `max` до неполной или пустой страницы.
- Время начала выборки фиксируется один раз в UTC. Поле
  `deletion_scheduled_at` должно содержать ровно одну ISO-дату с часовым
  поясом. Даты без часового пояса, невалидные значения и неоднозначные
  списки пропускаются с предупреждением и ID пользователя.
- Пользователь выбирается, когда срок удаления меньше или равен времени
  начала выборки. Поддерживаются UTC, Z и положительные/отрицательные
  смещения. Отсутствие срока удаления не является ошибкой.
- Выборка всех страниц завершается до начала удаления. При ошибке чтения
  страницы задача не получает частичный результат и не начинает удаление.
- Существующая независимая обработка ошибок удаления не меняется.
- `deploy/keycloak/sync.py`: добавить декларацию `deletion_scheduled_at`
  в существующий realm, чтобы срок удаления сохранялся после обновления.

## Проверки

Без новых файлов тестов в репозитории, согласно `CLAUDE.md`:

- проверочные команды с фиксированным временем и HTTP MockTransport:
  страницы 0/100/200, пустой список, полный размер последней страницы,
  будущие и просроченные сроки в разных поясах, точное равенство, Z,
  невалидные и наивные даты, несколько значений, сбой второй страницы;
- отдельный временный realm реального Keycloak с более чем 100
  пользователями: удаление просроченной записи за первой страницей,
  сохранение будущих и повреждённых записей, повторный запуск;
- существующие тесты, сборка образа API и `git diff --check`.

Один коммит после проверки. База `99643ad`, дата 03.11.2026.
AuthorDate и CommitDate нового коммита: `2026-11-08T02:42:04+03:00`.
