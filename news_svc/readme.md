# news_svc

Микросервис новостного блока sport_pari: лента, карточка материала и комментарии под ним.

Пользователь открывает блок новостей, фильтрует его по виду спорта, читает материал и оставляет комментарий. Аккаунты, линия и коэффициенты здесь не хранятся.

Сейчас маршруты и таблицы размечены, а запросы к базе ещё не написаны: репозитории поднимают `501 Not Implemented`.

## Стек

- **FastAPI**. Сервис уже на нём, BFF получает контракт из OpenAPI.
- **Postgres**. Лента — это сортировка и фильтр, комментарий — это ссылка на материал и автора. Для таких связей реляционная база подходит напрямую, и Postgres уже поднят в compose. Документная база была бы уместна, если тело новости станет деревом блоков. Пока это обычный текст, а если блоки появятся, их можно положить в JSONB, не вынося комментарии в другую базу.
- **SQLAlchemy 2 + asyncpg**. Тот же async-контур, что и у API. Сессии и миграции подключим, когда появятся первые запросы.

## Что нужно от других сервисов

- **Шлюз авторизации**. На запись комментария присылает заголовок `X-User-Id`. JWT этот сервис не проверяет и таблицу пользователей не заводит. Имена авторов для отрисовки собирает BFF из сервиса пользователей.
- **Каталог видов спорта**. `sport_id` на новости — это id каталога. Свой справочник видов спорта здесь не дублируется. Пока сервис каталога только источник идентификатора, отдельного клиента к нему нет.

Редакционное создание новости в эти маршруты не входит: снаружи есть чтение ленты и чтение карточки.

## Где что лежит

| Путь | Что здесь появится |
| --- | --- |
| `app/news/models.py` | таблица материалов |
| `app/news/repository.py` | лента и карточка |
| `app/news/schemas.py` | карточка без текста и полная карточка |
| `app/api/news.py` | `GET /api/v1/news`, `GET /api/v1/news/{id}` |
| `app/comments/models.py` | таблица комментариев |
| `app/comments/repository.py` | список и создание |
| `app/api/comments.py` | `GET` и `POST /api/v1/news/{id}/comments` |
| `app/api/deps.py` | чтение `X-User-Id` |
| `app/config.py` | `DATABASE_URL`, адреса user- и catalog-сервисов |
| `app/db.py` | общая metadata, позже engine и сессии |

## Запуск

Из каталога `news_svc`:

```bash
docker compose -f deploy/docker-compose.yml up --build
```

- API: http://localhost:8000
- OpenAPI: http://localhost:8000/docs

Проверка процесса:

```bash
curl -s http://localhost:8000/health
```

Лента и комментарии пока отвечают `501`.

Локально без контейнера API:

```bash
uv sync
uv run uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Образ собирается тем же `uv`: зависимости ставятся из `uv.lock`, каталог `app` импортируется из рабочей директории. Postgres в compose: база `news`, пользователь и пароль `news`, порт `localhost:5432`. Строка подключения — в `.env.example`.
